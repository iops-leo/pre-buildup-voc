## 개요

### 제품명
**몬스터 레이드** (Monster Raid - 협동 학습 게임)

### 목적
두 명의 아이(8-12세)가 태블릿에서 실시간으로 협력하며 몬스터와 전투하고 교육적 퀴즈를 푸는 협동 학습 게임입니다. 경쟁이 아닌 협력을 기반으로 재미있는 게이미피케이션을 통해 학습 동기를 높입니다.

### 핵심 가치
- **협력**: 경쟁이 아닌 협력을 통한 목표 달성
- **개별 맞춤**: 각 플레이어가 자신의 수준에 맞는 난이도를 선택
- **재미**: 게이미피케이션 요소로 학습을 즐거운 경험으로 변환
- **교육성**: 수학, 국어, 사회, 과학의 구조화된 문제 풀이

### 게임 특징
- 6자리 코드 기반 방 생성/참여 시스템
- 4개 월드 × 5마리 몬스터 + 히든 몬스터
- 실시간 협동 전투 (데미지 누적)
- 콤보/피버 게이미피케이션
- 개별 난이도 선택 가능
- 즉시 피드백 시스템 (올바른/틀린 답변)

### 사용자 시나리오

**시나리오 1: 형제자매 학습**
- 10살 언니와 8살 동생이 함께 플레이
- 언니는 "어려움" 난이도, 동생은 "쉬움" 난이도 선택
- 함께 몬스터를 물리치며 협력 경험 상승

**시나리오 2: 친구와 함께**
- 같은 반 친구 2명이 방과 후에 함께 플레이
- 같은 난이도로 경쟁하되 같은 몬스터를 협력해서 처치

**시나리오 3: 부모-자녀 학습**
- 부모가 자녀의 학습을 돕기 위해 함께 플레이
- 자녀의 약한 과목을 집중적으로 선택

## 핵심 가치 제안

### 협력 기반의 학습
- 두 플레이어가 같은 적을 협력해서 쓰러뜨림
- 누군가 실수해도 게임이 끝나지 않음 (누적 데미지)
- "우리가 함께 이겼다"는 성취감 제공

### 개인별 맞춤형 난이도
- 각 플레이어가 독립적으로 자신의 수준을 선택
- 강한 플레이어가 약한 플레이어의 부담을 나누지 않음
- 모두가 도전감을 느끼는 게임 경험

### 학습 콘텐츠의 다양성
- 4개 과목 × 4개 카테고리 × 3개 난이도 = 다양한 학습 경로
- 단순 암기가 아닌 사고력 기반 문제
- 교과과정과 연계된 정확한 학습 내용

### 게이미피케이션
- 데미지 피드백 (정답 시 몬스터 흔들림)
- 콤보 시스템 (3연속 이상 정답 시 1.5배 데미지)
- 피버 모드 (5연속 이상 정답 시 2배 데미지)
- 보상 시스템 (코인, XP 획득)

## 기능 요구사항

### 1. 로비 시스템

#### 1.1 방 생성 (Create Room)
- 플레이어 이름 입력 (최대 12자)
- 몬스터 선택 (20개 중 1개)
  - 4개 월드 × 5개 몬스터
  - 5개 히든/이벤트 몬스터
- 6자리 방 코드 자동 생성
- 방 생성 후 대기실로 진입

**기술 사양**
```
함수: createRoom(playerName: string, monsterId: string) -> string
출력: 6자리 방 코드 (예: "AB1C2D")
```

#### 1.2 방 참가 (Join Room)
- 플레이어 이름 입력
- 6자리 방 코드 입력
- 코드 유효성 검증
  - 존재하는 방인지 확인
  - 방이 가득 찼는지 확인 (최대 2인)
- 성공 시 대기실 진입

**기술 사양**
```
함수: joinRoom(code: string, playerName: string) -> boolean
유효성: code.length === 6, room.players.length < 2
```

### 2. 대기실 시스템 (Waiting Room)

#### 2.1 플레이어 구성
- 호스트 (Host): 방을 만든 플레이어
- 게스트 (Guest): 방에 참여한 플레이어

#### 2.2 설정 선택 (Player Config)
각 플레이어가 독립적으로 선택:

| 항목 | 선택지 | 기본값 |
|------|--------|--------|
| **과목** (Subject) | math, korean, social, science | math |
| **카테고리** (Category) | 과목별 4개 | - |
| **난이도** (Difficulty) | easy, normal, hard | easy |

**과목별 카테고리 상세**

수학 (Math):
- 덧셈 (addition): 쉬움(결과 1자리), 보통(결과 2자리), 어려움(결과 3자리)
- 뺄셈 (subtraction): 동일한 난이도 체계
- 구구단 (multiplication): 쉬움(2-5단), 보통(6-9단), 어려움(혼합+역산)
- 나눗셈 (division): 쉬움(나머지없음), 보통(나머지있음), 어려움(큰수)

국어 (Korean):
- 사자성어 (idiom): 초성 힌트 제공
- 속담 (proverb): 빈칸 채우기
- 맞춤법 (spelling): 올바른 표기 선택
- 반대말 (antonym): 유사한 의미 단어와 구분

사회 (Social Studies):
- 국기 맞추기 (flag): 이미지 → 국가명 입력
- 수도 맞추기 (capital): 국가명 → 수도명 입력
- 한국 지리 (koreaGeography): 지형/도시/문화재 문제
- 세계 지리 (worldGeography): 대륙/해역/산맥 문제

과학 (Science):
- 태양계 (solarSystem): 행성/위성/우주 개념
- 동물 (animal): 분류/생태/행동 특성
- 원소 (element): 원소기호/성질/반응
- 인체 (humanBody): 장기/골격/생리 기능

#### 2.3 준비 상태 (Ready System)
- 각 플레이어가 설정 완료 후 "준비" 버튼 클릭
- 두 플레이어 모두 준비 → "전투 시작" 활성화
- 호스트만 전투 시작 버튼 클릭 가능

### 3. 전투 시스템 (Battle System)

#### 3.1 전투 흐름
1. 질문 표시 (텍스트 또는 이미지)
2. 시간 제한 카운트다운
3. 플레이어 답변 입력
4. 즉시 판정 (정답/오답)
5. 데미지 적용 (정답만)
6. 다음 질문 로드

#### 3.2 질문 시스템

**질문 구성**
```typescript
interface Question {
  q: string;              // 문제 텍스트
  a: string;              // 정답
  options?: string[];     // 선택지 (선택지 문제인 경우)
}
```

**시간 제한 (난이도별)**

| 난이도 | 시간 제한 | 설명 |
|--------|---------|------|
| easy | 15초 | 충분한 시간, 생각할 여유 있음 |
| normal | 10초 | 표준 시간, 빠른 판단 필요 |
| hard | 7초 | 긴장감 있는 속도, 집중력 필요 |

#### 3.3 정답 판정 로직

```typescript
isCorrect = answer.trim().toLowerCase() === expectedAnswer.trim().toLowerCase()
```

**특수 처리**
- 연산식 정답의 경우: "/"로 분리된 여러 답변 모두 인정
  - 예: "feel/felt" → "feel" 또는 "felt" 모두 정답
- 공백 자동 제거
- 대소문자 무시
- 완전 일치 판정 (부분 일치 불가)

#### 3.4 데미지 계산 시스템

**기본 데미지 (난이도별)**

| 난이도 | 기본 데미지 |
|--------|-----------|
| easy | 10 |
| normal | 15 |
| hard | 25 |

**콤보 배수 (Combo Multiplier)**

| 연속 정답 | 데미지 배수 | 상태 |
|---------|-----------|------|
| 0-2개 | 1.0배 | 일반 |
| 3-4개 | 1.5배 | 콤보 상태 |
| 5개 이상 | 2.0배 | 피버 모드 |

**최종 데미지 계산**
```
finalDamage = baseDamage × comboMultiplier
예: normal 난이도 + 3연속 정답 = 15 × 1.5 = 22.5 → 23 (반올림)
```

**오답 처리**
- 데미지: 0
- 콤보: 초기화 (0)
- 몬스터 HP: 변화 없음
- 다음 질문으로 즉시 진행

#### 3.5 몬스터 상태

**HP 추적**
- 현재 HP: 전투 진행에 따라 감소
- 최대 HP: 몬스터별 초기 설정값
- 남은 HP %: UI에 프로그래스 바로 표시

**전투 종료 조건**
- 몬스터 HP ≤ 0 → 승리
- 전투 시간 제한 없음 (이론상 무한 진행 가능)
- 플레이어 연결 끊김 → 다시 연결될 때까지 일시 중지

### 4. 결과 화면 (Result Screen)

#### 4.1 승리 화면 정보

**플레이어별 통계**

| 항목 | 설명 | 예시 |
|------|------|------|
| 이름 | 플레이어 닉네임 | "영희" |
| 총 데미지 | 가한 데미지의 합 | "280" |
| 정답 개수 | 올바른 답변 수 | "28개" |
| 오답 개수 | 틀린 답변 수 | "2개" |
| 정답률 | 정답 개수 / (정답 + 오답) | "93.3%" |

**전투 정보**
- 몬스터명
- 몬스터 이미지/이모지
- 전투 소요 시간
- 총 질문 수

#### 4.2 보상 시스템

**코인 보상**
```
baseCoins = 몬스터.coinReward
totalCoins = baseCoins × (1 + 정답률 × 0.5)
```

**XP 보상**
```
baseXP = 정답개수 × 10
bonusXP:
  - 100% 정답률: +50
  - 80% 이상: +20
  - 그 외: +0
totalXP = baseXP + bonusXP (플레이어별 누적)
```

#### 4.3 배지 시스템 (향후 확장)
- 첫 승리 배지
- 100% 정답률 배지
- 특정 콤보 달성 배지
- 몬스터별 처치 배지

#### 1.2 몬스터 특성 (Traits)

**특성 체계**

| 특성 | 이름 | 효과 | 게임 영향 |
|------|------|------|---------|
| `poison` | 독 | 틀리면 다음 문제 시간 제한 50% 감소 | 전략적 어려움 |
| `freeze` | 빙결 | 틀리면 시간 제한 추가 감소 | 시간 압박 증가 |
| `burn` | 화상 | 오답 후 데미지 30% 감소, 정답 데미지 +20% | 회복 메커니즘 |
| `evade` | 회피 | 일정 확률(30%)로 데미지 무효 | 예측 불가능성 |
| `drain` | 흡수 | 오답 시 HP 5% 회복 | 전투 연장 |
| `rage` | 분노 | HP 50% 이하일 때 몬스터 데미지 감소 (방어 모드) | 후반 어려움 |
| `invisible` | 투명화 | 일시적으로 선택지 일부 숨김 | 난이도 급상승 |
| `revive` | 부활 | 1회 부활 가능 (HP 다시 50% 충전) | 예상 외 길어짐 |

#### 1.3 몬스터 데이터 구조

```typescript
interface Monster {
  id: string;              // 고유 ID (예: "green_slime")
  name: string;            // 한글명 (예: "초록 슬라임")
  emoji: string;           // 표시용 이모지
  world: number;           // 월드 ID (1-4, 0 = 히든)
  stage: number;           // 스테이지 (1-5, 0 = 히든)

  hp: number;              // 최대 HP
  traits: MonsterTrait[]; // 특성 배열
  coinReward: number;      // 코인 보상

}

type MonsterTrait =
  | 'poison'
  | 'freeze'
  | 'burn'
  | 'evade'
  | 'drain'
  | 'rage'
  | 'invisible'
  | 'revive';
```

## 게임 플로우

### 전체 흐름도

```
[시작]
  ↓
[로비 - RaidLobby]
  ├─ 방 만들기 (Host)
  │   ├─ 이름 입력
  │   ├─ 몬스터 선택
  │   └─ 코드 생성 → [대기실]
  │
  └─ 방 참가 (Guest)
      ├─ 이름 입력
      ├─ 코드 입력
      └─ 입장 → [대기실]

[대기실 - RaidWaitingRoom]
  ├─ 플레이어 1: 설정 선택
  │   ├─ 과목 선택
  │   ├─ 카테고리 선택
  │   ├─ 난이도 선택
  │   └─ 준비 클릭
  │
  └─ 플레이어 2: 설정 선택
      ├─ 과목 선택
      ├─ 카테고리 선택
      ├─ 난이도 선택
      └─ 준비 클릭
           ↓
      [둘 다 준비 상태]
           ↓
      Host: "전투 시작" 클릭
           ↓
[전투 - RaidBattle]
  ├─ 몬스터 표시
  ├─ 플레이어 HP/상태 표시
  │
  └─ 루프:
      1. 질문 표시
      2. 시간 제한 카운트다운
      3. 답변 입력/선택
      4. 즉시 판정
         ├─ 정답: 데미지 계산 → 데미지 적용
         └─ 오답: 콤보 초기화 → 다음 문제로
      5. 몬스터 HP 체크
         ├─ HP > 0: 다음 질문으로
         └─ HP ≤ 0: 전투 종료 → [결과]

[결과 - RaidResult]
  ├─ 승리 메시지
  ├─ 플레이어별 통계
  │   ├─ 데미지
  │   ├─ 정답률
  │   └─ 보상 (코인, XP)
  │
  └─ 버튼
      ├─ 다시 플레이 → [로비]
      └─ 홈으로 → [메인 화면]
```

### 상태 전이도 (State Diagram)

```
        ┌─────────┐
        │  lobby  │  ← resetRaid() 후 기본 상태
        └────┬────┘
             │ createRoom() / joinRoom()
             ↓
        ┌─────────┐
        │ waiting │  ← 대기실, 설정 선택
        └────┬────┘
             │ startBattle()
             ↓
        ┌─────────┐
        │ battle  │  ← 전투 중, 질문 반복
        └────┬────┘
             │ monsterHp = 0
             ↓
        ┌─────────┐
        │ result  │  ← 결과 화면, 통계 표시
        └─────────┘
```

### 플레이 시나리오

**시나리오: 10살 언니와 8살 동생이 몬스터 레이드 플레이**

1. **로비 진입**
   - 언니가 "방 만들기" → 이름 "언니" → 난이도 "어려움" 선택
   - 동생이 "방 참가" → 이름 "동생" → 방 코드 입력 → 난이도 "쉬움" 선택

2. **대기실**
   - 동생은 자신의 수준에 맞게 "수학-덧셈-쉬움"을 선택
   - 언니는 도전적으로 "수학-구구단-어려움"을 선택
   - 둘 다 "준비" 버튼 클릭

3. **전투 시작**
   - 초록 슬라임이 나타남 (HP 50)
   - 첫 번째 질문: 동생 화면에는 "2+3=?", 언니 화면에는 "7×8=?"
   - 동생: 5 입력 → 정답! 데미지 10
   - 언니: 56 입력 → 정답! 데미지 25 (어려움 난이도)
   - 총 35 데미지, 몬스터 HP: 50-35=15

4. **콤보 형성**
   - 3번 연속 정답 → "×3 콤보!" 팝업
   - 데미지가 1.5배 적용

5. **전투 종료**
   - 10문제 정도 풀고 몬스터 완전 처치
   - 화면 흔들림 + 컨페티 애니메이션

6. **결과**
   - 동생: 8정 2오, 정답률 80%, 코인 30 + 20(보너스)
   - 언니: 9정 1오, 정답률 90%, 코인 100 + 50(보너스)
   - 함께 이겼다는 성취감 + 개별 보상

## 제약사항 및 고려사항

### 기술 제약
- **오프라인 모드**: 현재는 로컬 멀티플레이만 지원 (같은 기기)
- **외부 API 의존성**: Supabase 실시간 기능 향후 필요
- **이미지 생성**: 현재 이모지만 사용, 일러스트는 향후 추가

### 게임 설계 고려사항
- **협력 난이도 밸런싱**: 각 플레이어의 다른 난이도가 전투 밸런스에 미치는 영향
- **콤보 시스템의 공정성**: 빠른 플레이어가 느린 플레이어보다 더 많은 콤보를 쌓지 않도록 주의
- **문제 난이도 일관성**: 난이도가 실제로 일관된지 지속적으로 검증 필요

### 콘텐츠 관리
- **저작권**: 사용된 모든 교육 콘텐츠가 저작권 보호 상태인지 확인
- **교육과정 정렬**: 한국 초등학교 교과과정과의 일치성 유지
- **검증**: 전문 교사의 검수를 통한 정확성 확보
